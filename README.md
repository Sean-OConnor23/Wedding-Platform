# Wedding-Platform
This is the website I have created for my upcoming wedding. It utilizes a variety of Azure Services that I have learned about while completing my AI-200 certification.

## Azure Services Used:
1. Azure AI Foundry
2. Azure AI Search (Free Tier)
3. Azure Functions (Serverless Microservices Compute)
4. Azure Blob Storage (Cloud File Storage Engine)
5. Azure AI Vision (Multi-Modal Machine Learning)
6. Azure Resource Groups
7. Azure Key Vault
8. Azure App Configuration
9. Azure Cosmos DB

## Activity Log
#### July 30
- I used Azure AI Search to upload my data for my FAQ Assistant using cloud storage. I created an index that has two indexers (One for JSON and one for Doc/PDF files). This way, I can upload a .json, .docx, or .pdf file into my azure storage and it will be parsed. I have my check for new indexing set to once a day. As we get wedding details I can upload and everything will be handled automatically. This removes the need to store wedding information inside my actual code base.
- For the photo processor, I have added automatically uploading the photo tags generated by Azure Vision to an Azure Cosmos DB NoSQL database. When I finish the front end, users will be able to filter by these tags to narrow down which pictures they are looking for.
- To speed up starting my local server, I created a .ps1 file to batch all of my calls.
- I also installed Node.js and Cursor today. I plan to start using Cursor with Claude Code.
  
#### July 26
- I used Azure Vision and Azure Blob Storage to create a backend that accepts .jpg images, uploads them to blob storage, and attaches tags to them. When the image us uploaded, a blob trigger processes the image and returns tags so that future work will be able to categorize these images. The intent of this work is so that the wedding party will be able to upload images from the reception, rehearsal dinner, ceremony, etc.
- In addition, I broke the Azure Function endpoints into their own files using Azure Functions Blueprints. This helped achieve some separation of concerns which is critical when trying to achieve clean code.
- Once I got this working utilizing keys in local.settings.json, I moved all of my api keys and connection strings into Azure Key Vault. I moved other configuration values to Azure App Configuration where there is also a reference to the aforementioned Azure Key Vault. Now that my backend has access to this Azure App Configuration, it will be simpler to put this website into production.  

#### July 14
- I setup the initial backend project structure. Within this, I have used Python Virtual Environment (.venv) alongside the Azure Functions Python V2 Programming Model. Currently, I utilize the local.settings.json file paired with a Python .gitignore to store app secrets.
- Through Azure AI Search, I created a database schema index to outline wedding specific faqs. I inserted temporary placeholders for proof of concept. This is where my wedding platform and model will retrieve the data necessary to interact with a user.
- With Azure AI Foundry, I deployed a gpt-5.4-model and an exposed endpoint to allow the user to interact. (Using Data Zone Standard deployment).
- All of this is contained in one Azure Resource Group so I can isolate resources used and easily manage costs and other things under one sole umbrella.
- Overall:  My Azure Functions app acts as the middleman between Azure AI Foundry and Azure Search. A user prompts a question which then gets sent to Azure Search. Azure Search uses vector indexing and information provided to return (to Azure Function App) information it deems relevant to the question. From there, this data is passed into Azure AI Foundry where a user-friendly response is generated and passed back to Azure Function for display to the user.

### General Knowledge Learned:
1. RAG Architecture (Retrieval-Augmented Generation)
   - AI architectural pattern that improves a Large Language Model (LLM) by forcing it to retrieve facts from an external database before generating an answer.
   - Three Steps of RAG:
     1. R (Retrieval): System searches a database to find documents matching the user's question.
     2. A (Augmentation): The system appends those documents into the LLM's system prompt as a reference text block.
     3. G (Generation): The LLM reads the added text and generates a natural, factually accurate response.
2. Azure Blob Storage
   - BLOB --> Binary Large Object
